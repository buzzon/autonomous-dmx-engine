# Phase 3 Implementation Plan - Расширение data-driven системы и ImGui UI

## Обзор
**Цель Phase 3:** Довести систему до production-ready состояния, реализовав недостающие критические компоненты, улучшив Audio Analyzer, добавив REST API и аутентификацию, а также создав продвинутый UI на ImGui для управления и конфигурации.

**Сроки:** 4-5 недель (детальный план ниже)

## Текущее состояние (после Phase 2)
✅ **Выполнено в Phase 2:**
- Реальная обработка аудио с FFT, beat detection и BPM estimation
- Реальный DMX вывод через Art-Net с профессиональными функциями
- WebSocket API и базовый Web UI (ImGui)
- Система конфигураций площадок
- Unit тесты для новых компонентов

⚠️ **Недостающие компоненты (требуются в Phase 3):**
- Mood classification в Audio Analyzer
- REST API и аутентификация JWT
- Наследование конфигов и визуальный редактор
- Тестирование с реальным оборудованием
- Расширенные data-driven правила и ML адаптация

## 1. Улучшение Audio Analyzer

### 1.1 Mood Classification
**Задача:** Реализовать классификацию настроения музыки (calm, energetic, intense) на основе спектральных характеристик и BPM.

**План:**
1. **Исследование и проектирование** (2 дня)
   - Анализ существующих подходов (energy-based, valence-arousal)
   - Определение фичей: spectral centroid, flux, zero crossing rate, BPM, energy history
   - Пороговые значения для классификации

2. **Реализация классификатора** (3 дня)
   - Создать `src/audio/features/moodClassifier.ts`
   - Реализовать простой rule-based классификатор (можно позже заменить на ML)
   - Интеграция с AudioAnalyzer и worker

3. **Тестирование и калибровка** (2 дня)
   - Тесты с различными аудио треками
   - Калибровка порогов по реальным данным

### 1.2 Дополнительные Spectral Features
**Задача:** Добавить больше спектральных характеристик для улучшения анализа.

**План:**
1. **Реализация features** (2 дня)
   - Spectral rolloff (85%, 95%)
   - Mel-frequency cepstral coefficients (MFCC) - базовые 13 коэффициентов
   - Spectral contrast
   - Добавить в `src/audio/features/spectralFeatures.ts`

2. **Интеграция в AudioMetrics** (1 день)
   - Расширение интерфейса `AudioMetrics`
   - Обновление worker для вычисления новых фичей

### 1.3 Оптимизация производительности
**Задача:** Убедиться, что Audio Analyzer работает в real-time без лагов.

**План:**
1. **Профилирование** (1 день)
   - Измерение времени обработки фрейма
   - Выявление bottlenecks

2. **Оптимизация** (2 дня)
   - Использование WebAssembly для тяжёлых вычислений (FFT)
   - Предвычисление lookup tables
   - Улучшение memory management в worker

## 2. Расширение ControlAPI

### 2.1 REST API
**Задача:** Предоставить HTTP REST API для управления системой и конфигурациями.

**План:**
1. **Проектирование endpoints** (1 день)
   - `GET /api/status` - статус системы
   - `GET /api/metrics` - текущие метрики аудио
   - `POST /api/command` - отправка команд (mode, intensity, blackout)
   - `GET /api/configs` - управление конфигурациями
   - `POST /api/configs` - загрузка новых конфигов

2. **Реализация Express сервера** (3 дня)
   - Создать `src/control/rest/` модуль
   - Интеграция с существующим ControlAPI
   - Middleware для логирования и ошибок

3. **Документация OpenAPI** (2 дня)
   - Генерация Swagger спецификации
   - UI документация доступная по `/api-docs`

### 2.2 Аутентификация JWT
**Задача:** Защитить API и WebSocket соединения аутентификацией.

**План:**
1. **Проектирование системы ролей** (1 день)
   - Роли: admin, operator, viewer
   - Разрешения для каждой роли

2. **Реализация JWT middleware** (2 дня)
   - Генерация токенов при логине
   - Верификация токенов в REST API и WebSocket
   - Refresh tokens

3. **Логин через ImGui UI** (2 дня)
   - Форма логина в ImGui интерфейсе
   - Сохранение токена в localStorage

## Риски и mitigation

| Риск | Вероятность | Влияние | Mitigation |
|------|-------------|---------|------------|
| Сложность реализации mood classification | Средняя | Среднее | Начать с простого rule-based подхода, ML отложить |
| Производительность ImGui с большим количеством виджетов | Низкая | Низкое | Оптимизация рендеринга, virtual scrolling |
| Проблемы совместимости с реальным DMX оборудованием | Высокая | Высокое | Тестирование с multiple devices, fallback на mock |
| Нехватка времени на все компоненты | Средняя | Высокое | Приоритизация: сначала REST API и mood classification |

## Критерии успеха Phase 3

1. **Audio Analyzer:** Mood classification работает с accuracy >80% на тестовом наборе
2. **REST API:** Все endpoints работают, защищены аутентификацией

4. **ImGui UI:** Dashboard предоставляет всю необходимую информацию, mobile-friendly
5. **Тестирование:** Система работает стабильно 24+ часа, latency DMX <50ms
